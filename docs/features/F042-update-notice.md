## ทำไม

หลัง release คนที่เปิดแท็บค้างไว้ยังรันโค้ดรุ่นเก่า ไม่รู้ว่ามีรุ่นใหม่ และอาจเจอพฤติกรรมไม่ตรงกับ server รุ่นใหม่

## สิ่งที่ผู้ใช้จะเห็น

1. ผู้ใช้เปิดหน้าใดก็ได้ (โต๊ะ, หน้าเริ่ม, เดโม) บน staging หรือ production
2. pipeline deploy รุ่นใหม่ขึ้น environment นั้น
3. ภายใน ~5 นาที (หรือทันทีที่กลับมาที่แท็บ / ต่อเน็ตได้อีกครั้ง) มีแถบด้านล่างจอ: **มีเวอร์ชันใหม่ (vX.Y.Z) รีเฟรชหน้าเพื่อใช้รุ่นล่าสุด** · ปุ่ม **รีเฟรช** / **ไว้ทีหลัง**
4. **ไว้ทีหลัง** ซ่อนแถบสำหรับรุ่นนั้น ถ้ามีรุ่นใหม่กว่าอีกจะขึ้นใหม่

## ขอบเขต

**รวม:** ทุกหน้าใน SPA, staging และ production (แต่ละ environment เทียบกับ `/version` ของตัวเอง), Node runtime ที่ serve `dist/`
**ไม่รวม:** บังคับรีเฟรชอัตโนมัติ (อาจทำข้อความที่พิมพ์ค้างหาย), push ผ่าน WebSocket ของห้อง, Vite dev server (ไม่มี build identity จึงไม่เช็ค)

## ข้อเท็จจริงจากโค้ด (2026-10-22)

- `vite.config.ts` สร้าง build identity ครั้งเดียว → เขียน `version.json` และฝังลง bundle เป็น `__TABLETOP_BUILD__` (ค่าเดียวกัน)
- `/version` (Worker `cloudflare/index.ts`, Node `server/app.ts`) ตอบ `Cache-Control: no-store` อยู่แล้ว
- release pipeline build ครั้งเดียวแล้ว deploy ทั้ง staging/production ด้วย build เดียวกัน → sha ที่ฝังตรงกับ `/version` ของทั้งสองที่
- `src/update-notice/` — `version-check.ts` (เทียบ version + sha, sha `unknown` ไม่นับเป็นหลักฐาน) และ `UpdateNotice.tsx` mount ใน `src/main.tsx`
