## ทำไม

ลองโต๊ะ "หารบิลทริปเพื่อน" (5 คน ใบเสร็จ 23 ใบ หารเท่ากันก่อน แล้วแก้กฎกลางทางว่าคนหนึ่งไม่ได้ไปทัวร์เรือ) บน `wrangler dev` กับ AI จริงเมื่อ 2026-10-23 ตัวเลขออกมาถูกทุกขั้น แต่เจอปัญหาสองข้อ

1. ตอนแก้กฎ AI เพิ่ม collection ใหม่ (ยอดปรับต่อคน, แผนโอนใหม่) แล้วใส่ข้อมูลผ่าน**ปุ่มที่ไม่มี input และไม่มีเงื่อนไข** โดยฝังตัวเลขที่ AI คิดเองเป็น `literal` ตัวเลขพวกนี้ไม่เปลี่ยนตามใบเสร็จ และถ้า AI คิดเลขพลาด ระบบก็จับไม่ได้
2. กดปุ่มนั้นซ้ำแล้วแถวซ้ำ ยอดค้างโอนเพิ่มเป็นสองเท่า (7,471.8 → 14,943.6)

ต้นเหตุ: กฎที่แก้กลางทางใส่ `initialRecords` ไม่ได้ (`TABLE_PRESERVE_DATA` ใน `applyTableChange`) และ prompt บอกว่า collection ใหม่ "เริ่มว่าง" และแนะนำปุ่ม sample ที่ค่าเป็น literal

## สิ่งที่ผู้ใช้จะเห็น

- ร่างกฎจาก AI ที่มีปุ่มแบบนี้จะถูกส่งกลับไปให้ AI ซ่อมก่อนถึงมือผู้ใช้ (repair loop เดิม) พร้อมเหตุผลว่าต้องใส่เงื่อนไขกันกดซ้ำ หรือเปลี่ยนไปใช้สูตร
- ปุ่มที่ผ่านจะกดได้ครั้งเดียว (เช่น เงื่อนไข count ของ collection = 0) กดครั้งที่สองขึ้นข้อความของเงื่อนไข
- AI ถูกบอกให้ทำตัวเลขที่คำนวณจากข้อมูลได้ (ยอดรวม ส่วนแบ่ง ยอดคงเหลือ) เป็นสูตรใน metric/chart ซึ่งอัปเดตเองเมื่อข้อมูลเปลี่ยน

## ขอบเขต

**รวม:** ตัวตรวจ `repeatableFixedCreateIssues` / `aiTableChangeIssues` ใน `domain/table.ts` · ใช้กับร่างจาก AI ใน `cloudflare/ai.ts` · คำแนะนำ `DERIVED VALUES` ใน `server/providers/table-schema-guide.ts` · เทสต์

**ไม่รวม:**
- ไม่แตะ `server/providers/deepseek-changes.ts` เพราะ F065 จองไว้ (`doing`) · ประโยค "collection ใหม่เริ่มว่าง" และคำแนะนำปุ่ม sample ใน system prompt ยังอยู่ ให้ F065 ปรับให้สอดคล้อง (ดูคำถามเปิด)
- ไม่เปลี่ยน `checkProgram`/`tableChangeIssues` ซึ่งใช้ตอนย้อนรุ่น, ลบกฎย่อย และ manual proposal
- โต๊ะเก่าที่มีปุ่มแบบนี้อยู่แล้วยังกดซ้ำได้เหมือนเดิม
- ยังไม่มีวิธีคำนวณ "ใครโอนให้ใคร" แบบ live ทั้งชุด (ต้องจับคู่ลูกหนี้/เจ้าหนี้) · ปุ่มที่สร้างแผนจากสูตรตอนกด (`{expression}`) ผ่านได้

## ข้อเท็จจริงจากโค้ด (ตรวจ 2026-10-23 บน `origin/dev` 868bc3a)

- `applyTableChange` ห้าม `initialRecords` เมื่อมี program อยู่แล้ว (`src/tabletop/domain/table.ts` "A rule edit must preserve current records")
- `checkProgram` ถูกเรียกจาก `applyTableChange` และ `removeTableRuleItem` · `restoreRevision` ใน `evolution.ts` ส่ง snapshot เก่ากลับผ่าน `applyTableChange` → ถ้าใส่กฎใหม่ที่นี่ โต๊ะเก่าจะย้อนรุ่น/ลบกฎย่อยไม่ได้
- ร่างจาก AI ผ่าน `proposeChange` / `proposeGeneratedTable` ใน `cloudflare/ai.ts` ซึ่งเรียกตัวตรวจแล้วส่ง issues เข้า repair
- evaluator ส่ง scope ซ้อน (`new Map(scope)`) ทำให้ `aggregate` ภายใน chart value อ่าน `row` ของ chart ได้

## คำถามเปิด

- F065 ควรแก้ system prompt ส่วนแก้กฎ: เลิกพูดว่า collection ใหม่ "เริ่มว่าง" แบบไม่มีทางเลือก และให้ปุ่ม sample มีเงื่อนไขกันกดซ้ำ
- ควรอนุญาต `initialRecords` สำหรับ collection ที่เพิ่มใหม่ในการแก้กฎไหม (ไม่แตะแถวเดิม) — ลดความจำเป็นของปุ่ม seed แต่ค่าก็ยังเป็นตัวเลขที่ AI คิดเอง
