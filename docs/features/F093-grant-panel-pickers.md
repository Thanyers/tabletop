## ทำไม

กล่อง **ให้ห้องอ่านข้อมูลจากโต๊ะนี้** ([F080](F080-custom-tools-joined-tables.md) D-054/D-055) ขอสามอย่างที่คนกดไม่รู้คำตอบ

1. **ห้องที่จะให้สิทธิ์** เป็น dropdown ที่ลิสต์ **ทุก workspace ในเซสชัน** ยกเว้นโต๊ะที่เปิดอยู่ เพราะรายการ `/tables` ไม่ได้บอกว่า workspace ไหนเป็นห้อง · ตัวเลือกส่วนใหญ่จึงเป็นโต๊ะธรรมดาที่ไม่มีทางเป็นปลายทางที่ถูกต้อง และยังบังคับให้เลือกทั้งที่เคสปกติมีห้องเดียวคือห้องที่โต๊ะนี้เพิ่งสร้าง
2. **ตาราง (resource) ที่ให้อ่าน** เป็นช่องพิมพ์เปล่า ทั้งที่ชื่อ collection อยู่ในกฎของโต๊ะอยู่แล้ว
3. **ฟิลด์ที่ให้เห็น** ให้พิมพ์คั่นด้วยจุลภาค พิมพ์ผิดหนึ่งตัวก็รู้ตอน command ถูกปฏิเสธ

ทั้งสามข้อผลักภาระการจำ id ให้คน ทั้งที่โต๊ะรู้คำตอบอยู่แล้ว

ระหว่างลองของจริงยังเจออีกสองข้อที่ทำให้ไม่มีทางมีห้องให้เลือกตั้งแต่แรก (แก้ใน PR เดียวกัน เพราะ F093 พิสูจน์ในแอปไม่ได้ถ้าไม่แก้)

4. **สร้างห้องจากโต๊ะไม่เคยสำเร็จ** — `createRoom` ส่ง `{ spaceId, title }` แต่ `createSchema` บังคับ `sharedToolWorkspaceId` ด้วย ทุกคำขอจึงได้ `422 SPACE_PAYLOAD` ตั้งแต่ D-050
5. **แล้วยังรายงานว่าสำเร็จ** — `runCommand` แจ้งเตือนแล้วคืน `null` ไม่ throw `catch` ของ `createRoom` จึงไม่ทำงาน กล่องขึ้น "สร้างห้องแล้ว: /s/…" และพาไปหน้าห้องที่ไม่มีอยู่จริง

## สิ่งที่ผู้ใช้จะเห็น

1. เปิดเมนู **ห้อง** → **ให้ห้องอ่านข้อมูลจากโต๊ะนี้**
2. ถ้าโต๊ะเกี่ยวข้องกับห้องเดียว กล่องบอกว่า "ให้สิทธิ์ห้อง **<ชื่อห้อง>**" ไม่มี dropdown ให้กด · มีหลายห้องจึงมี dropdown และ **ห้องแรกถูกเลือกไว้แล้ว**
3. **ตาราง (resource)** เป็น dropdown ของ collection ในกฎของโต๊ะ (ตารางแรกถูกเลือกไว้)
4. **ฟิลด์ที่ให้เห็น** เป็นรายการ checkbox ของฟิลด์ในตารางนั้น · เริ่มต้นไม่ติ๊กอะไรเลย — การแสดงรายการไม่ใช่การเลือกแทนคน · เปลี่ยนตารางแล้วรายการฟิลด์เปลี่ยนตามและล้างที่ติ๊กไว้
5. โต๊ะที่ยังไม่เกี่ยวข้องกับห้องไหนเห็นข้อความให้ไปสร้างห้องก่อน แทนฟอร์มที่กดส่งไม่ผ่าน
6. โต๊ะที่ยังไม่มีกฎ (ไม่มี collection) ยังได้ช่องพิมพ์แบบเดิม

## ขอบเขต

**รวม:** `SpaceGrantPanel`, ตัวเลือกที่ `TabletopApp` ส่งให้, สไตล์ checkbox ใน `room-setup.css`, harness ของ D-050/D-051

**ไม่รวม:** authority และ payload ของ `source.grantProjection` (ไม่เปลี่ยน), การถอนสิทธิ์, การแสดงสิทธิ์ที่ให้ไปแล้ว, การเพิ่มธงบอก "เป็นห้อง" ลง `WorkspaceListItem` (ดู คำถามเปิด)

## ข้อเท็จจริงจากโค้ด (ตรวจ 2026-11-07 บน dev `cc29c0a`)

- `TabletopApp.tsx` เดิมสร้าง `grantRooms` จาก `session.workspaces` ทั้งหมดที่ไม่ใช่โต๊ะปัจจุบัน และตั้ง `spaceId: workspace.id` ซึ่งเป็น **workspace id ไม่ใช่ slug ของห้อง** — payload จึงถูกเฉพาะตอนสองค่านี้บังเอิญตรงกัน
- `space.create` รันบน workspace ที่เปิดอยู่ แล้วเก็บ `collaborationSpace` ไว้ใน `TableState` ของโต๊ะนั้นเอง → **โต๊ะที่สร้างห้องคือโต๊ะที่ host ห้องนั้น** และรู้ทั้ง `spaceId` และ `title` จริง
- `TableState.spaceGrants: ToolProjectionGrant[]` เก็บห้องที่โต๊ะนี้เคยให้สิทธิ์ (`spaceWorkspaceId` + `spaceId`) — เป็นหลักฐานอีกชุดว่า workspace ไหนเป็นห้อง
- `TableProgram.collections[].id/title` และ `.fields[].id/label` คือ resource และ field ที่ grant อ้างถึง
- `WorkspaceListItem` มีแค่ `id/title/kind/role` — `kind` เป็น case kind (`table`/`invoice`/…) ไม่ได้บอกว่า host ห้องอยู่หรือเปล่า

## คำถามเปิด

- รายการห้องตอนนี้เห็นเฉพาะห้องที่โต๊ะนี้ host หรือเคยให้สิทธิ์ · ห้องที่ **เชื่อมโต๊ะนี้เป็น source แล้วแต่ยังไม่ได้ขอสิทธิ์** ยังไม่อยู่ในรายการ เพราะ `sources` เก็บอยู่ที่ห้องไม่ใช่ที่โต๊ะ · ถ้าต้องการต้องให้ฝั่ง server บอกมาด้วย (ธงใน `WorkspaceListItem` หรือ endpoint "ห้องที่อ้างถึงโต๊ะนี้") — แยกเป็นงานใหม่
