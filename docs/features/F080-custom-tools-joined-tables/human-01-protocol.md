# HUMAN-01 — protocol for the real-user check

เกณฑ์: **ผู้ใช้จริง 5 คน เว้น 3 วัน อย่างน้อย 4 คน** บอกได้ว่า *อะไรเปลี่ยน / ใครทำ / เหตุผลที่มีหลักฐาน* และ **เริ่มขั้นถัดไปได้ภายใน 30 วินาที**

เอกสารนี้เป็นขั้นตอนที่คนอื่นทำแทนไม่ได้ (agent ไม่สามารถนั่งดูผู้ใช้จริงได้) — เป้าหมายคือให้ผลลัพธ์เอาไปกรอก `acceptance.json` ได้ทันที

## 1. ก่อนเริ่ม (10 นาที)

- เปิด dev/staging ที่มีงาน F080 (ดู `closure-checklist.md`)
- เตรียมห้องตัวอย่าง 1 ห้องที่มี **2 แหล่งข้อมูล** และมี recap ที่บอกว่ามีแหล่งถูกถอน 1 แหล่ง
- เตรียมผู้ใช้ 5 คนที่ไม่เคยเห็นฟีเจอร์นี้มาก่อน (ห้ามอธิบายล่วงหน้า)
- เตรียมตัวจับเวลา (นาฬิกา/มือถือ) และฟอร์มบันทึกท้ายเอกสารนี้

## 2. งานที่ให้ผู้ใช้ทำ (ไม่เกิน 5 นาที/คน)

1. เปิดห้อง แล้วบอกว่า **ห้องนี้กำลังทำอะไร** (อ่าน brief)
2. หาให้ได้ว่า **แหล่งข้อมูลใดอ่านไม่ได้** และบอกว่าต้องทำอะไรต่อ
3. ดูข้อมูลรวมจาก 2 แหล่ง แล้วบอกว่า **แถวไหนมาจากแหล่งไหน**
4. เรียก action หนึ่งครั้ง (เช่น "จองห้อง") แล้วบอกว่า **เกิดอะไรขึ้น**
5. หา **recap** ที่บอกว่ามีอะไรเปลี่ยนตั้งแต่ครั้งก่อน

ห้ามใบ้ ห้ามชี้หน้าจอ ถ้าติดให้พูดว่า "ลองหาต่อเอง" และบันทึกว่าติดตรงไหน

## 3. ทิ้งช่วง 3 วัน

- ห้ามแตะห้องของผู้ใช้แต่ละคนระหว่างนี้ (ให้ข้อมูลขยับเองตามปกติถ้ามี)
- วันที่ 4 กลับมาถาม 4 ข้อ:

| # | คำถาม | ผ่านเมื่อ |
|---|---|---|
| Q1 | "อะไรเปลี่ยนไปตั้งแต่ครั้งก่อน" | ระบุการเปลี่ยนแปลงได้อย่างน้อย 1 อย่างที่ตรงกับความจริง |
| Q2 | "ใครทำ" | บอกชื่อ/บทบาทผู้ที่กระทำได้ถูกต้อง |
| Q3 | "รู้ได้อย่างไร" | ชี้หลักฐานในจอได้ (revision/ผู้เขียน/เวลา) ไม่ใช่เดา |
| Q4 | "ขั้นถัดไปที่คุณจะทำคืออะไร" | เริ่มทำได้จริงภายใน **30 วินาที** (นับจากการถามจบ) |

**ผ่านรายคน** = ตอบ Q1–Q3 ได้ + Q4 ทำได้ใน 30 วินาที
**ผ่านเกณฑ์** = ผ่านอย่างน้อย 4 จาก 5 คน

## 4. ตารางบันทึกผล (คัดลอกไปใช้)

```
รุ่น/SHA ที่ทดสอบ:
สภาพแวดล้อม: dev / staging (ระบุ URL)
วันที่เริ่ม:               วันที่ถามซ้ำ:

| คน | Q1 เปลี่ยน | Q2 ใคร | Q3 หลักฐาน | Q4 เวลา (วินาที) | ผ่าน |
|----|-----------|--------|-------------|------------------|------|
| 1  |           |        |             |                  |      |
| 2  |           |        |             |                  |      |
| 3  |           |        |             |                  |      |
| 4  |           |        |             |                  |      |
| 5  |           |        |             |                  |      |

ผ่าน ___ / 5  →  เกณฑ์ผ่าน ≥ 4/5:  ใช่ / ไม่ใช่
```

## 5. บันทึกผลกลับเข้า repo

แก้ `docs/features/F080-custom-tools-joined-tables/acceptance.json` ที่รายการ `HUMAN-01`:

```json
{
  "id": "HUMAN-01",
  "status": "PASS",
  "environment": "human",
  "sha": "<commit ที่ทดสอบ>",
  "commands": ["<ลิงก์ฟอร์มหรือไฟล์ผลที่เก็บไว้>"],
  "evidence": "5 users, 3-day gap, 4/5 answered changed-by-whom-why-with-evidence and started the next step within 30 seconds",
  "actual": "PASS at the human environment",
  "limitations": "<อะไรที่ยังไม่ครอบคลุม>"
}
```

## 6. สิ่งที่ทำให้ผลใช้ไม่ได้

- ผู้ใช้เห็นฟีเจอร์มาก่อน หรือถูกอธิบายก่อนทำ
- ไม่ได้เว้น 3 วันจริง
- จับเวลาแบบประมาณ ("น่าจะเร็ว") แทนการจับจริง
- สรุปผลจากคำบอกเล่าของผู้ทดสอบเองโดยไม่มีหลักฐานบนจอ (Q3)
