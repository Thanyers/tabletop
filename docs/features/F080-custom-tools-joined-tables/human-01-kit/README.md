# HUMAN-01 kit — ทำให้ผลการทดสอบกับผู้ใช้จริง "ตรวจได้"

เกณฑ์ HUMAN-01 (ผู้ใช้จริง 5 คน เว้น 3 วัน ≥4 คนผ่าน) ทำแทนไม่ได้โดย agent แต่สิ่งที่ทำได้คือทำให้**ผลลัพธ์ตรวจสอบได้ด้วยสคริปต์** ไม่ใช่คำบอกเล่า

## ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| [`results-template.csv`](results-template.csv) | แม่แบบบันทึกผล (5 แถว) — คัดลอกแล้วกรอกระหว่างทดสอบ |
| [`../human-01-protocol.md`](../human-01-protocol.md) | ขั้นตอนทดสอบ, คำถาม 4 ข้อ, สิ่งที่ทำให้ผลใช้ไม่ได้ |
| `scripts/check-human-01-results.mjs` | ตรวจไฟล์ผลก่อนบันทึกเป็นหลักฐาน |

## ขั้นตอน

1. คัดลอกแม่แบบไปไว้ที่ `test-results/human-01-results.csv` (gitignored — **ห้าม commit ข้อมูลผู้ใช้จริง**)
2. กรอก `start_date` และ `repeat_date` (ต้องห่าง ≥3 วัน) แล้วบันทึกผลรายคน
   - `q1_changed` = ตอบได้ว่าอะไรเปลี่ยน · `q2_who` = ใครทำ · `q3_evidence` = ชี้หลักฐานบนจอได้
   - `next_step_seconds` = เวลาจริง (วินาที) ที่ใช้เริ่มขั้นถัดไป — **จับด้วยนาฬิกา ไม่ใช่ประมาณ**
   - `pass` = `yes` เฉพาะเมื่อ q1–q3 = yes **และ** `next_step_seconds` ≤ 30
3. ตรวจ:
   ```bash
   node scripts/check-human-01-results.mjs test-results/human-01-results.csv
   ```
   ผ่าน = exit 0 และขึ้น `5 passed · 0 failed`

## สิ่งที่สคริปต์บังคับ (เพื่อไม่ให้ "ผ่าน" แบบไม่จริง)

- มี 5 ผู้เข้าร่วมครบ และทุกคนมีเวลาจริง > 0
- ระยะห่างวันที่ ≥ 3 วัน
- **ให้คะแนนตรงกับคำตอบ**: ถ้า q1–q3 ไม่ครบ หรือเกิน 30 วินาที แต่เขียน `pass=yes` ⇒ FAIL
- ผ่านอย่างน้อย 4/5

## ตัวอย่างผลลัพธ์

ไฟล์ที่กรอกครบและถูกต้อง:
```
PASS  the study waited at least three days — 4 days
PASS  five participants were recorded — 5 rows
PASS  at least four participants passed — 4 of 5
5 passed · 0 failed
```

**แม่แบบที่ยังไม่กรอกจะ FAIL เสมอ** (`1 passed · 9 failed`, exit 1) — ตั้งใจให้เป็นแบบนั้น เพื่อไม่ให้ใครคัดลอกแม่แบบไปอ้างว่าเป็นผลจริง

ไฟล์ที่ระยะห่าง 1 วัน หรือผ่านแค่ 2/5 ก็ได้ exit 1 พร้อมข้อความ `HUMAN-01 cannot be recorded as PASS from this file.`

## ทำไมไม่มีหน้า HTML สำหรับกรอก

ผมทำหน้า form แล้วรัน `ui-gate` ปรากฏว่าไม่ผ่าน (emoji, contrast 21 สถานะ, touch target) จึง**ไม่ ship** สิ่งที่คุณภาพไม่ถึงเกต — CSV + สคริปต์ตรวจให้ผลเหมือนกันโดยไม่ต้องมี UI เพิ่ม

## สิ่งที่ต้องเตรียมก่อน (ผู้ดูแลต้องทำ — D-049)

UI ปัจจุบัน **ไม่มี** ปุ่มสร้างห้องหรือติดตั้ง tool ⇒ ก่อนทดสอบ ผู้ดูแลต้อง:

1. สร้าง workspace ลูก (โต๊ะ) 2 อัน แล้ว import ไฟล์ตัวอย่างลงแต่ละอัน
2. สร้างห้อง: ส่งคำสั่ง `space.create` (slug + title) ไปที่ workspace ที่จะเป็นห้อง
3. เชื่อม 2 โต๊ะ: `space.addSource` + ให้สิทธิ์อ่าน (grant) ที่ต้นทาง
4. ถอน 1 แหล่ง (เพื่อให้ recap บอกว่ามีแหล่งถูกถอน)
5. ติดตั้ง tool: `space.installTool` พร้อม `definition` (package ที่ activate แล้ว)
6. ส่ง URL `/s/<slug>` ให้ผู้ทดสอบ 5 คน

คำสั่งทั้งหมดนี้ต้องทำด้วย session ของผู้ดูแลเอง — ห้ามใช้บัญชีอื่นหรือ credential ที่แชร์กัน
