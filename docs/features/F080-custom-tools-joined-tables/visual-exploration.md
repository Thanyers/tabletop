# F080 · สำรวจภาพ: เครื่องมือที่แชร์จากสองตาราง

สถานะ: **ยังไม่ได้เลือกทาง** — ต้นแบบ 3 แบบผ่านไดรเวอร์เดียวกัน (PASS ทั้ง 3) เอกสารนี้รายงานผลวัด ไม่ใช่ข้อสรุปแบบ

## งานเปรียบเทียบ (ลำดับเดียวกันทุกแบบ)

1. `table-budget` โฟกัสตารางงบประมาณของเพื่อน (ขอบหนาขึ้น + ป้าย “กำลังดู”)
2. `port-price` + `port-devices` เปิดพอร์ตจากคนละตาราง (`button aria-pressed`)
3. `create-shared-tool` สร้างเครื่องมือ แล้วต้องเห็นทั้ง “ผังกิจกรรม · rev 3” และ “งบประมาณ · rev 7”
4. `status-budget` สถานะเป็นข้อความ + รูปทรง (● live / ▲ stale / ✕ revoked)
5. `table-mine` กลับตารางตัวเอง ข้อมูลเดิมยังอยู่
6. `disconnect-budget` ถอนงบประมาณ → เครื่องมือยังอยู่ สถานะ “ถูกถอน” ค่า price/device กลายเป็น “ไม่พร้อมใช้ — เชื่อมใหม่”

## สิ่งที่แต่ละ metaphor ทำให้ง่าย / ยาก

- **A ผังพื้น:** เข้าใจง่ายสุดว่าโต๊ะอยู่ตรงไหนและกำลังดูโต๊ะไหน เพราะทุกอย่างอยู่ในระนาบเดียว แต่พอโต๊ะเยอะขึ้น พื้นที่จะแออัดและต้องจัดตำแหน่งเอง
- **B มุมเฉียง:** สื่อ “สองโต๊ะอยู่ในห้องเดียวกัน” และความลึกได้ดีกว่าแบบแบน แต่ข้อความถูกฉายเอียงตามระนาบ (อ่านได้แต่ไม่สบายตา) และการวางตำแหน่งต้องเผื่อการบิดของระนาบ
- **C Canvas:** เพิ่มการ์ดได้เรื่อย ๆ และพอร์ตอยู่ในแผงข้างเดียวกันชัดเจน แต่เสียความรู้สึกว่าเป็นห้องเดียวกัน และการเลื่อน/ซูมด้วยปุ่มเท่านั้นทำให้ไปถึงการ์ดไกล ๆ ช้ากว่า

## คีย์บอร์ด · มือถือ · reduced motion

- คีย์บอร์ด: เดินครบ 6 ขั้นด้วย Tab + Enter ทั้ง 3 แบบ และไดรเวอร์วัด `:focus-visible` ที่หนา ≥ 2px ทุกครั้งที่โฟกัส
- มือถือ: ที่ 320 และ 414 ไม่มี horizontal overflow (`scrollWidth == innerWidth` ตามตาราง) และโหมดโฟกัสโต๊ะเดียวถูกยืนยัน (ข้อมูลโต๊ะที่ไม่ได้ดูถูกซ่อน)
- reduced motion: ภายใต้ `prefers-reduced-motion: reduce` ความยาว transition ที่คำนวณได้ทุกองค์ประกอบเป็น 0s ทั้ง 3 แบบ
