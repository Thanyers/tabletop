## ทำไม

ตอนนี้การเชิญต้องเลือกที่นั่งทีละที่ ได้ลิงก์ที่ **ใช้ได้ครั้งเดียว หมดอายุใน 10 นาที** ต้องส่งลิงก์ใหม่ให้ทีละคน ผู้ใช้อยากได้ลิงก์เดียวของโต๊ะนี้ ส่งในกลุ่มแชทแล้วทุกคนกดเข้าร่วมได้

## ⚠️ ผลต่อความปลอดภัย

แบบเดิมตั้งใจให้ลิงก์หลุดแล้วเสียหายน้อยที่สุด ลิงก์ใช้ซ้ำได้ทำให้ **ใครก็ตามที่ได้ลิงก์ไป เข้าโต๊ะได้จนกว่าเจ้าของจะปิด** ฟีเจอร์นี้จึงต้องมีทั้งหมดนี้ก่อนเปิดใช้:

- **ปิดเป็นค่าเริ่มต้น** เจ้าของต้องกดเปิดเองทุกโต๊ะ
- เจ้าของ **ปิดลิงก์** ได้ทันที และ **สร้างลิงก์ใหม่** (ลิงก์เก่าใช้ไม่ได้ทันที)
- **มีวันหมดอายุ** (ค่าเริ่มต้นตามคำถามเปิดข้อ 2)
- ยังต้อง **ล็อกอิน Google** ก่อนเข้าร่วม และนับเพดานสมาชิกของโต๊ะ (Worker สูงสุด 12 คน ตั้งต่ำกว่านั้นได้ด้วย Member limit · Node runtime 7 คน)
- เจ้าของ **เอาสมาชิกออก** ได้ (ตอนนี้ทำไม่ได้ นอกจากรีเซ็ตทั้งห้อง) → T1 ต้องเสร็จก่อน
- เก็บ token แค่ hash · rate limit การใช้ลิงก์ · บันทึกทุกการเข้าร่วมในประวัติ · ลิงก์ไม่ติดใน log, analytics หรือ `Referer`
- รีเซ็ตห้อง (epoch ใหม่) → ลิงก์เดิมใช้ไม่ได้

ลิงก์เชิญแบบครั้งเดียวต่อที่นั่งยังอยู่เหมือนเดิม

## สิ่งที่ผู้ใช้จะเห็น

1. หน้าต่าง **People at this table** สำหรับโต๊ะข้อมูล **ไม่มีส่วน AVAILABLE SEATS แล้ว** แสดงแค่รายชื่อคนที่อยู่ในโต๊ะ พร้อมตัวนับที่นั่ง เช่น `1/7`
2. ใต้รายชื่อมีส่วน **ลิงก์เชิญของโต๊ะนี้** (เจ้าของเท่านั้น): สวิตช์เปิด/ปิด · ปุ่ม **Copy link** · วันหมดอายุ · ปุ่ม **สร้างลิงก์ใหม่** · ระบบเลือกที่นั่งว่างให้เอง ผู้เชิญไม่ต้องเลือก
3. คนที่กดลิงก์ → ล็อกอิน Google → เห็นชื่อโต๊ะกับเจ้าของ → กด **เข้าร่วม** → ได้ที่นั่ง `member-N` ที่ว่างตัวแรก
4. ลิงก์ปิด/หมดอายุ/เต็ม (`7/7`) → เห็นข้อความบอกเหตุผลและให้ติดต่อเจ้าของ ไม่บอกข้อมูลในโต๊ะ
5. รายชื่อสมาชิกมีปุ่ม **เอาออก** สำหรับเจ้าของ

## ขอบเขต

**รวม:** ห้องชนิด `table` (ที่นั่ง `member-1`…`member-7` ใช้แทนกันได้) · Worker และ Node runtime · เอาสมาชิกออก

**ไม่รวม (รอบนี้):** `teaching` และ `encounter` เพราะที่นั่งผูกบทบาท (learner, Mira/Pip) · เปิดโต๊ะให้คนไม่ล็อกอินดู · ลิงก์แบบดูอย่างเดียว

## ข้อเท็จจริงจากโค้ด (2026-10-20)

- สร้างลิงก์ครั้งเดียว: `POST /api/workspaces/:id/invites {seat, replaceOutstanding}` (`client.ts`) · UI `InviteDialog` ใน `TabletopApp.tsx` มีปุ่ม Copy link อยู่แล้ว
- ลิงก์ใส่ ticket ใน URL fragment (`#invite=...`) จึงไม่ถูกส่งไปเซิร์ฟเวอร์และไม่ติด `Referer` → ใช้หลักเดียวกัน
- ใช้ลิงก์: `POST /api/invites/redeem {ticket}` ผ่าน Room DO (`/internal/redeem`) · เก็บเฉพาะ hash · rate limit `redeem` 20/นาที/คน (`cloudflare/index.ts`)
- เพดานสมาชิก `MAX_MEMBERS_PER_WORKSPACE` (`server/limits.ts`) ตรวจทั้ง Node และ Room
- ที่นั่ง: `Seat` ใน `src/tabletop/shared/contracts.ts` · `table` ใช้ `TABLE_MEMBER_SEATS` (`member-1`…`member-12` บน Worker; Node runtime ใช้ `member-1`…`member-7`)
- ไม่มีคำสั่งเอาสมาชิกออก · `MEMBERSHIP_REVOKED` มีอยู่แล้วและ WebSocket ตรวจสิทธิ์ซ้ำทุกครั้งที่ส่ง → คนที่ถูกเอาออกจะหยุดได้รับข้อมูล
- ดัชนี My tables อยู่ใน D1 และ sync ผ่าน outbox ที่เรียงลำดับ → การเอาออกต้องส่ง outbox ด้วย

## คำถามเปิด

1. คนที่เข้าผ่านลิงก์ต้องให้เจ้าของ **อนุมัติก่อน** ไหม หรือเข้าได้ทันที? (อนุมัติก่อนปลอดภัยกว่า แต่เจ้าของต้องออนไลน์)
2. ลิงก์หมดอายุเมื่อไร? (เสนอ: ค่าเริ่มต้น 7 วัน เจ้าของเลือก 1 วัน / 7 วัน / 30 วัน)
3. จำกัดจำนวนครั้งที่ใช้ลิงก์ได้ไหม หรือใช้ได้จนที่นั่งเต็ม?
4. ตัวนับนับเจ้าของด้วยไหม? ตอนนี้เพดานคือเจ้าของ + สมาชิก 7 คน (`MAX_MEMBERS_PER_WORKSPACE = 8`) · เสนอ: นับเฉพาะที่นั่งสมาชิก เจ้าของอยู่คนเดียวแสดง `0/7` แล้วแสดงเจ้าของแยกในรายชื่อ
