## ทำไม

ระหว่างที่การ์ดหนึ่งกำลังทำงาน (เช่น "Preparing a rule draft…") ปุ่ม Send ถูกปิด ส่งงานถัดไปไม่ได้จนกว่างานแรกจะเสร็จ ซึ่งงานร่างกฎใช้เวลาได้ถึงหลายนาที

## สิ่งที่ผู้ใช้จะเห็น

1. ระหว่างรอ พิมพ์และกด Send ได้ตลอด
2. **คำถาม** (โหมด ask) เริ่มทันทีและทำขนานกับงานอื่น ได้หลายใบพร้อมกัน (server จำกัด 8 งานต่อโต๊ะ)
3. **คำขอร่างกฎ** ที่ส่งตอนมีร่างอื่นกำลังทำ ขึ้นการ์ด "Rule draft · queued" พร้อมปุ่ม **Cancel this request** แล้วเริ่มเองเมื่อร่างก่อนหน้าเสร็จ โดยเริ่มจากโต๊ะหลังร่างก่อนหน้า (ร่างที่สองต่อยอดร่างแรก)
4. การ์ดที่กำลังทำของคนอื่นขึ้นให้ทุกคนเห็นสด (open visibility, F034) ชื่อคนถามขึ้นเป็นบรรทัดเล็กสีจางใต้หัวข้อการ์ด (เดิมต่อหน้าหัวข้อ "ชื่อ: …") และข้อความรอบอกชื่อ เช่น "Alice is preparing a rule draft…" จะได้ไม่ส่งงานซ้ำ · ร่างกฎของคนอื่นที่กำลังทำก็นับเป็นงานที่กำลังทำ ร่างของเราจึงเข้าคิวต่อ ไม่ชนกัน · การ์ดที่ยัง *queued* อยู่ในหน้าเว็บของผู้ส่งเท่านั้น คนอื่นเห็นตอนเริ่มทำจริง
5. ยังส่งไม่ได้เฉพาะตอนมี proposal รอ Confirm/Skip, กำลัง Confirm action หรือมีคำขอที่ไม่แน่ใจว่า server ได้รับ (ต้องกด Retry ก่อน)

## ขอบเขต

**รวม:** client queue + parallel ask, server เก็บคำตอบที่โต๊ะเปลี่ยนระหว่างสร้าง · **ไม่รวม:** ร่างกฎขนานกันจริง (โต๊ะมีร่างได้ทีละอัน), คิวข้ามเครื่อง/ข้ามคน (คิวอยู่ในหน้าเว็บของผู้ส่ง ปิดแท็บแล้วคิวที่ยังไม่เริ่มหาย)

## ข้อเท็จจริงจากโค้ด (2026-10-22)

- `src/tabletop/ui/useTableChat.tsx`: เดิม `requestsBusy` (การ์ดใด ๆ `sending`/`waiting`) + `requestLock` ปิด Send ทั้งหมด
- `cloudflare/room.ts` `runTableAssistantJob`: เดิมเช็ค `revision` หลังโมเดลตอบ ถ้าโต๊ะเปลี่ยน (เช่นร่างกฎอีกใบเสร็จ หรือมีคนกด action) คำตอบธรรมดาก็ล้มเป็น `STALE_WORKSPACE`
- งานร่างกฎ (`/model`) ล้ม `STALE_WORKSPACE` ถ้า revision เปลี่ยนระหว่างสร้าง และโต๊ะมี candidate ได้ทีละอัน → ร่างขนานกันจะทับ/ล้มกัน จึงต้องเข้าคิว
- การ finish งาน assistant ไม่ bump revision ของโต๊ะ → คำถามหลายใบไม่ทำให้กันล้ม
