## ทำไม

ผู้ใช้ต้องการให้โต๊ะใหม่ดูว่างจริง และคุยกับโต๊ะผ่านช่องแชทอย่างเดียว ตอนนี้กด "Start empty with your own files" แล้วมีการ์ด Files/Rules และแชท (Table assistant) เป็นกล่องใหญ่ที่มีหัวข้อ โหมด Set up คำอธิบาย และ checkbox ยินยอมค้างอยู่

## สิ่งที่ผู้ใช้จะเห็น

1. โต๊ะข้อมูลที่เพิ่งสร้าง **ไม่มีการ์ดเลย** มีแค่ Canvas ว่าง
2. **ช่องแชทแถวเดียว** อยู่กึ่งกลางขอบล่างตลอด · พิมพ์ยาวแล้วขยายขึ้นได้สูงสุด 5 แถว · ในช่องมีแค่ปุ่มแนบไฟล์ (คลิปหนีบ) และปุ่มส่ง ไม่มีหัวข้อหรือคำอธิบายอื่น
3. แนบไฟล์ได้จากคลิปหนีบหรือ **ลากไฟล์วางบนโต๊ะ** → การ์ดไฟล์โผล่บนโต๊ะเมื่อมีไฟล์จริง
4. กดส่ง **ครั้งแรก** ในโต๊ะนั้น (และเมื่อขอบเขตเปลี่ยน) → แถบเหนือช่องบอกว่าคำขอ กฎ/ข้อมูล/เทิร์น และไฟล์ชื่อใดจะส่งให้ AI การถามโต๊ะใช้ประวัติส่วนตัวที่เกี่ยวข้องและไม่ส่งไฟล์ต้นฉบับ ส่วนการร่างกฎใช้ไฟล์ที่แสดงและไม่ส่งประวัติแชท [ส่ง] [ยกเลิก]
5. ข้อความแรกของเจ้าของในโต๊ะที่ยังไม่มีกฎ = **ขอให้ AI ร่างกฎ** → ร่างโผล่เป็น **การ์ดกฎ** ให้ตรวจ Simulate → Validate → Approve → Activate (ไม่เปิดใช้อัตโนมัติ)
6. หลังมีกฎ ข้อความ = **ถามโต๊ะ** (คำอธิบาย / ขอเตรียมหนึ่ง action) → **คำตอบแปะเป็นการ์ดใหม่บนโต๊ะ** · การ์ดที่เสนอ action มีปุ่ม Confirm แยก
7. สมาชิกที่ไม่ใช่เจ้าของ: ช่องเดียวกัน ใช้ถามโต๊ะ (ไม่มีแนบไฟล์และไม่ร่างกฎ)
8. หลังเปิดใช้กฎ เจ้าของยังเลือก **Edit rules** จากการ์ด Rules แล้วพิมพ์แก้ผ่านช่องแชทเดิมได้; **Cancel rule edit** ยกเลิกข้อความที่ยังไม่ส่งและกลับไปถามโต๊ะ ข้อความถามโต๊ะทั่วไปไม่เปิดใช้กฎหรือแก้ข้อมูลเอง

## ขอบเขต

**รวม:** ทุกห้องชนิด `table` · component แชทใหม่ (ไม่แก้ `TableAssistant` ใช้ของใหม่แทนในโต๊ะข้อมูล) · ซ่อนการ์ด Files/Rules เมื่อยังไม่มีของ · คำตอบเป็นการ์ด · ยินยอมตอนกดส่ง · ปรับ browser tests

**ไม่รวม:** ห้อง invoice / teaching / encounter (ยังใช้ AI ตามเดิม) · เปลี่ยน API ฝั่งเซิร์ฟเวอร์ (ใช้ `table.import`, `/model`, `/assistant`, `/assistant/:job/confirm` เดิม) · ลบโค้ด `TableAssistant` (ทำแยกหลังใช้ของใหม่ครบ)

## กติกาที่ต้องคงไว้

- **ยินยอมก่อนส่งทุกครั้งที่ข้อมูลที่จะส่งเปลี่ยน** (ข้อความใหม่ไม่ต้องถามซ้ำ แต่ไฟล์ใหม่ต้องถาม) · ไม่เก็บการยินยอมข้ามโต๊ะหรือข้ามการรีโหลด
- AI **ไม่เปิดใช้กฎเอง** และ **ไม่ทำ action เอง** — ยังต้องผ่าน Simulate → Validate → Approve → Activate และ Confirm action
- ไฟล์ต้นฉบับยังเป็นของเจ้าของห้องเท่านั้น · แชทยังแยกตามผู้ถาม
- AI ปิด (เช่น local งบเป็น 0) → ช่องยังพิมพ์ได้แต่ส่งไม่ได้ และบอกเหตุผลสั้น ๆ ในตัวช่อง (placeholder) · แนบไฟล์ยังทำได้
- คงการสร้างจากข้อความโดยไม่มีไฟล์จาก F005; ไม่เพิ่มเงื่อนไขบังคับแนบไฟล์
- การส่ง/ยืนยันที่ไม่ทราบผลต้องตรวจสถานะหรือใช้ command ID เดิมเมื่อผู้ใช้ลองซ้ำ; ไม่เปลี่ยน revision ของข้อเสนอให้ดูใหม่โดยอัตโนมัติ และไม่ล้างข้อความก่อนรู้ว่าส่งสำเร็จ
- การยินยอมผูกกับโต๊ะ epoch ผู้ถาม และชุดไฟล์ที่แสดงจริง; เปลี่ยนห้อง รีเซ็ต หรือรีโหลดต้องยินยอมใหม่

## คำตอบสำหรับการต่อเข้ากับ F005

การ์ดคำตอบอ่านจากประวัติส่วนตัวที่เซิร์ฟเวอร์มีอยู่แล้วและเปิดกลับได้หลังรีโหลด; การปิดและตำแหน่งการ์ดเป็นมุมมองส่วนตัว ไม่เขียนคำตอบลง shared records หรือ shared layout ไม่มี retention/storage ใหม่ใน F006

เจ้าของเริ่มจากข้อความโดยไม่มีไฟล์ได้ตาม F005 และต้องตรวจร่างก่อนเปิดใช้เหมือนเดิม การมีไฟล์เป็นทางเลือกสำหรับเพิ่มข้อมูลอ้างอิง
