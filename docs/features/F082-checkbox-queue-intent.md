## ทำไม

ตอนทดสอบ todo list บน staging หลัง [F081](F081-checkbox-toggle.md) (2026-10-26) เจอสองเรื่อง:

1. ติ๊ก checkbox หลายช่องติดกันเร็ว ๆ แล้วบางช่องไม่ถูกบันทึก เพราะ checkbox ทั้งการ์ดถูก `disabled` ระหว่างบันทึกช่องก่อนหน้า คลิกที่ตกช่วงนั้นหายเงียบ
2. ข้อความขอแก้กฎหรือโครงตาราง เช่น "ปรับกฎ…ให้ช่อง done ทำเครื่องหมายและเอาออกได้" ถูกส่งไปเป็นคำสั่งกดปุ่ม (act) แทนร่างกฎ เพราะ `classifyChatIntent` เจอคำว่า "ทำเครื่องหมาย" ก่อนแล้วตัดสินทันที

## สิ่งที่เปลี่ยน

- **คิว checkbox** (`ui/TableCanvasObjects.tsx`): คลิกแต่ละครั้งเข้าคิวและแสดงผลทันที (optimistic, `aria-busy` ระหว่างรอ) · คิวรันทีละงานตามลำดับ อ่านค่าล่าสุดของแถวก่อนรัน ถ้าค่าตรงกับที่ต้องการแล้วก็ข้าม · checkbox ถูก disabled เฉพาะเมื่อไม่มีกฎที่ติ๊กได้ ไม่ใช่ระหว่างบันทึก · ทุกคลิกยังผ่าน `table.act` ของ server เหมือนเดิม (server authority ไม่เปลี่ยน)
- **ตัวจัดประเภทข้อความ** (`shared/chat-intent.ts`): ก่อนเช็คคำกริยาแก้ข้อมูล ให้เช็คว่าข้อความขอโครงสร้าง (ตาราง/ฟอร์ม/ปุ่ม/การ์ด + คำว่าเพิ่ม/แก้) หรือขอกฎ (กฎ/เงื่อนไข/สูตร/คำนวณ + เพิ่ม/แก้/ใหม่/แทน) หรือไม่ โดยตัดวลีแก้ข้อมูลออกก่อนตรวจ ถ้าใช่ → ร่างกฎ (edit) · ข้อความที่แค่สั่งทำเครื่องหมายแถวยังเป็น act
