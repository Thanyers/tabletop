## ทำไม

- หน้า landing ปนสองภาษา: หัวข้อเป็นอังกฤษ เนื้อหาเป็นไทย ทั้งที่ `lang="th"`
- การ์ด "Approve before use" ไม่ตรงกับ F039 ที่กฎจาก AI เปิดใช้อัตโนมัติหลังผ่านการตรวจ
- ความสามารถที่ออกไปแล้วไม่อยู่บนหน้า: แชทเริ่มโต๊ะ, live cursor, เห็นทุกอย่างในโต๊ะ, role ต่อคน, note card
- รูปเดโมสูงผิดปกติ: `<img height=928>` ทับ `aspect-ratio` บนมือถือรูปละ 1,050px
- ปุ่มเริ่มใช้งานมีแค่ด้านบน

## สิ่งที่ผู้ใช้จะเห็น

1. ปุ่มสลับภาษาที่หัวหน้า (`English` / `ไทย`) เปลี่ยนทั้งหน้า รวมกล่องเข้าสู่ระบบและ welcome back · จำค่าที่เลือกไว้ใน `localStorage` (`tabletop.landingLanguage`) · ค่าเริ่มต้นอังกฤษ · `<html lang>` เปลี่ยนตาม
2. ลำดับใหม่: hero → เหตุผล → ลองอะไรได้วันนี้ + เดโม → ทิศทาง (3 lens) → แถบปิดท้ายพร้อมปุ่ม → footer
3. การ์ดความสามารถ 3 ใบเขียนใหม่ตามรุ่นปัจจุบัน (ข้อความที่ผู้ใช้อนุมัติ 2026-10-22)

## ขอบเขต

**รวม:** `PublicWelcome`, `AccountSignIn`, `SignedInWelcome`, CSS ของ landing · **ไม่รวม:** แปลตัวแอปหลังล็อกอิน, ข้อความแจ้งเตือนจาก server, URL แยกภาษา (`/en`) + `hreflang`, prerender

## ข้อเท็จจริงจากโค้ด (2026-10-22)

- ข้อความทั้งสองภาษาอยู่ที่ [`src/tabletop/ui/landing-copy.ts`](../../src/tabletop/ui/landing-copy.ts) ที่เดียว (`th` เป็นต้นแบบของ type, `en` ต้องมีครบทุกช่อง)
- คอมโพเนนต์อ่านข้อความด้วย `useLandingCopy()` ภายใต้ `LandingLanguageContext` ที่ `PublicWelcome` ให้
- ไม่เพิ่ม dependency

## คำถามเปิด

- `index.html` ยังเป็น `lang="th"` และ title/description ภาษาไทย ขณะที่หน้าเริ่มเป็นอังกฤษ: ต้องเลือกว่าจะเปลี่ยน title/description เป็นอังกฤษหรือไม่ (กระทบ OG tag ของ F051)
- SEO: ปุ่มสลับฝั่ง client ทำให้ index ได้ภาษาเดียว (อังกฤษ) ถ้าต้องการให้ค้นเจอภาษาอังกฤษด้วย ต้องแยก URL `/en` + `hreflang` (ประสานกับ [F051](F051-seo-baseline.md))
