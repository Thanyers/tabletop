## ทำไม

- โต๊ะรับไฟล์ได้ 64 KiB (`TABLE_TOTAL_SOURCE_BYTES`) แต่คำขอร่างกฎรับข้อมูลโต๊ะได้แค่ 48,000 bytes รวมกฎ ข้อมูล และข้อความ
- ผู้ใช้แนบไฟล์ได้ถูกกติกา แต่ใช้ร่างกฎไม่ได้ (เจอ "The files and request are too large")
- เลข 48 KB ไม่มีเหตุผลบันทึกไว้ (มีมาตั้งแต่ `6532f3e`) และกระจายอยู่ 4 ที่:
  - `MAX_TABLE_INPUT_BYTES` ใน provider และใน `ai.ts`
  - `MAX_CHANGE_REQUEST_BYTES` 64,000 ซึ่งรวม system prompt ราว 20 KB ทำให้ข้อมูลจริงได้แค่ ~44 KB
  - การจอง token ของ billing 65,000 (`MAX_INPUT_TOKENS` ใน `billing.ts` และ `MAX_PROVIDER_INPUT_TOKENS` ใน `ai.ts`)

## สิ่งที่เปลี่ยน

- `TABLE_AI_INPUT_BYTES = 128 KiB` อยู่ที่ `domain/table.ts` = ไฟล์เต็มโควตา 64 KiB + อีก 64 KiB ให้กฎ ข้อมูล และข้อความ
- ค่าที่คำนวณจากตัวนี้:
  - `MAX_CHANGE_REQUEST_BYTES` = ข้อมูลโต๊ะ + 32 KiB สำหรับ system prompt และ envelope
  - การจอง token สูงสุด = request bytes + margin (นับ 1 byte ≤ 1 token) ทั้งใน `ai.ts` และ `billing.ts`
- ข้อความ "File limits" ในการ์ดไฟล์อัปเดตตาม

**ไม่รวม:** แชทถามตอบ (เพดาน 48 KiB ของตัวเอง ตาม F041/F044) และ invoice

## ผลกระทบ

- คำขอใหญ่ที่สุดจอง token ราว 165,000 (เดิม 65,000)
- ระบบไม่มีเพดานเงินโดยค่าเริ่มต้น (F036) จำกัดแค่จำนวนงานต่อวัน และคิดเงินตามที่ใช้จริง
- คำขอที่ใหญ่ขึ้นใช้เวลาอ่านนานขึ้น แต่ยังอยู่ใต้เวลา 240 วินาทีต่อการร่าง
