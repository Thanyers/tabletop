# Auto demo และประวัติทดสอบ

Auto demo รันโจทย์จาก persona หลายแบบกับ Cloudflare Worker, D1 และ Room Durable Object **ในเครื่อง** แล้วสร้างรายงาน HTML ที่เล่นย้อนขั้นตอนจริงจากผลรอบนั้นได้ ข้อมูลบัญชีและห้องเป็นข้อมูลจำลอง ไม่มีการเรียก Google หรือ AI จริง และไม่ส่งคำสั่งไปห้อง production

รอบส่งมอบวันที่ 19 ตุลาคม 2026 ผ่าน **9 สถานการณ์ / 166 ข้อตรวจ** ดู [รายงานเล่นย้อนหลัง](../handoff/Final/auto-demo/0926de9d-b570-4229-a6a9-3e10f5e2d7d8/report.html), [ผล JSON](../handoff/Final/auto-demo/0926de9d-b570-4229-a6a9-3e10f5e2d7d8/run.json) และ [ขอบเขตการตรวจ](../handoff/Final/auto-demo/README.md) ไฟล์ HTML เปิดแบบ offline ได้ หรือใช้คำสั่งดูรอบที่เก็บไว้ด้านล่าง

## เปิดดูและรันซ้ำ

หลังติดตั้ง dependencies ด้วย `npm ci`:

```powershell
npm run demo:auto
npm run demo:auto:view
```

เปิด `http://127.0.0.1:4311/` เพื่อเลือกโจทย์ ดู persona เปรียบเทียบผลที่คาดกับผลจริง และกดเล่น/หยุด/ย้อนขั้นตอน การกดเล่นเป็นการอ่านบันทึก ไม่ส่งคำสั่งใหม่ ไม่เรียก AI และไม่เปลี่ยนห้องใด

ดูรอบส่งมอบที่อยู่ใน Git โดยไม่ต้องรันทดสอบใหม่:

```powershell
npm run demo:auto:view -- --file handoff/Final/auto-demo/0926de9d-b570-4229-a6a9-3e10f5e2d7d8/report.html
```

`demo:auto` ตรวจและ build โค้ดก่อนรัน หาก build ล่าสุดพร้อมแล้ว ใช้ `npm run demo:auto:run` ได้ การรันคืน exit code ที่ไม่สำเร็จเมื่อพบผลผิดคาด โดยยังเก็บผลที่ทำไปแล้วไว้ให้ตรวจ

แต่ละรอบสร้างโฟลเดอร์ใหม่ใน `test-results/auto-demo/<run-id>/` พร้อม `run.json` และ `report.html` ไม่เขียนทับรอบก่อน `latest.json` เป็นตัวชี้ไปผลล่าสุดเท่านั้น ค่า source commit, เวลา, รุ่นของสถานการณ์ และขอบเขตของ runtime อยู่ในรายงาน ใช้ชื่อ scenario และผล checkpoint เปรียบเทียบรอบ ไม่เทียบ UUID หรือเวลาให้เหมือนกัน

`workerBundleSha256` ระบุไฟล์ Worker ที่ใช้จริง ส่วน `sourceCommit` กับ `sourceDirty` ระบุสภาพ source ตอนรัน คำสั่ง `demo:auto:run` ใช้ bundle ที่ build ไว้ จึงต้อง build ใหม่เองหากเปลี่ยน source; คำสั่ง `demo:auto` และ CI ทำขั้นนี้ให้ก่อนรัน

## ปุ่ม Auto demo สำหรับคนทั่วไป

เปิด [Auto demo บนเว็บ](https://tabletop.ptchrr.workers.dev/demo) หรือกดปุ่ม **Auto demo** บนหน้าล็อกอิน หน้ารวมโต๊ะ หรือแถบของโต๊ะที่เปิดอยู่ บนหน้าจอแคบ ปุ่มในโต๊ะอยู่ในเมนูเลือกโต๊ะ ลิงก์เปิดแท็บใหม่เพื่อเก็บสิ่งที่กำลังทำในโต๊ะเดิมไว้

หน้า `/demo` เปิดได้โดยไม่ล็อกอิน มี 9 เรื่องในสามกลุ่ม: ตรวจบิล ห้องเรียน และเกมร่วมมือ เลือก persona/โจทย์ แล้วกดเล่น หยุด ย้อน ไปต่อ เริ่มใหม่ หรือเลือกจังหวะจากลำดับได้ ค่าในหน้าจอคือ checkpoint ล่าสุดที่มีบันทึก และระบุจังหวะต้นทางเสมอ

เผยแพร่และตรวจบนเว็บจริงแล้ววันที่ 19 ตุลาคม 2026 ดู [รายงานรอบเผยแพร่](../handoff/Final/planning-review/TABLETOP_R1_PUBLIC_AUTO_DEMO_RELEASE_2026-10-19.md) สำหรับรุ่นที่ deploy ผล CI การตรวจ browser และข้อจำกัด

นี่คือการเล่นย้อนหลังจากรอบทดสอบด้วยข้อมูลจำลอง ไม่ใช่การส่งคำสั่งเข้าโต๊ะจริงหรือเรียก AI การเปิดหน้าใหม่เริ่มที่เรื่องแรก ไม่สร้างบัญชี session หรือห้อง และไม่บันทึกความคืบหน้าในเครื่อง ผู้ที่ต้องการแก้โจทย์หรือชวนคนมาเล่นจริงให้กลับหน้าหลักและล็อกอิน

ข้อมูลสาธารณะสร้างจาก archive ที่ตรึง SHA-256 ไว้ใน `scripts/generate-public-demo.mjs` โดยคัดเฉพาะ persona คำอธิบาย และตัวเลข checkpoint ไม่รวมประวัติห้องจริง, actor/room ID, คำสั่ง, cookie หรือผล API ฉบับเต็ม `npm run build` ตรวจว่าไฟล์ที่สร้างตรงกับแหล่งอ้างอิงก่อน build ทุกครั้ง หากแก้ถ้อยคำในตัวสร้าง ให้รัน `node scripts/generate-public-demo.mjs` แล้วทบทวน diff ก่อน commit

## Persona และความหลากหลาย

| กลุ่ม | Persona / โจทย์ | สิ่งที่ต้องเห็น |
| --- | --- | --- |
| ตรวจบิล | คุณอ้อม เจ้าของร้าน: ยังไม่มีเอกสารค่าพื้นที่ห่างไกล | แยกยอดที่รู้กับรายการ Unknown และบอกหลักฐานที่ขาด |
| ตรวจบิล | คุณนก ผู้ดูแลบิล: เปลี่ยนอัตราตามวันที่และเก็บผลรอบเดิม | Draft ไม่เปลี่ยน Active; ตรวจผลก่อน/หลังเปิดใช้และ saved run |
| ตรวจบิล | คุณก้อง ผู้ตรวจทาน: กฎซ้อนหรือคำสั่งซ้ำ | ปฏิเสธกฎที่ใช้ไม่ได้ และไม่ทำรายการซ้ำ |
| ห้องเรียน | ครูเมย์กับฟ้าและต้น: เรียนโจทย์เดียวกันด้วยมุมมองต่างกัน | ตั้งมุมมองแยกคน และไม่ส่งคำตอบหรือบันทึกส่วนตัวข้ามผู้เรียน |
| ห้องเรียน | ผู้เรียนที่เปิดโจทย์เก่าค้างไว้ | ไม่รับคำตอบผิด revision และไม่รับค่ามวลนอกช่วง |
| ห้องเรียน | ผู้เรียนลองแก้โจทย์ครูหรืออ่านคำตอบเพื่อน | ปฏิเสธคำสั่งและไม่ส่งข้อมูลส่วนตัวข้ามคน |
| เกมร่วมมือ | DM วิน, Mira และ Pip: ป้องกันเพื่อน | ตรวจการเปิดกติกา และ HP/AP หลังรับมือการโจมตี |
| เกมร่วมมือ | DM ลองตัดสินผลขณะหยุดเกม และผู้เล่นลองสั่งเล่นต่อ | ปฏิเสธทั้งสองคำสั่ง แล้ว DM เล่นต่อและตัดสินผลได้ |
| ทบทวนร่าง | เจ้าของกลับมาที่ร่างเก่าหลังเวลาที่อนุมัติไว้ | ปฏิเสธ approval ที่หมดอายุ และทบทวนก่อนเปิดใช้ใหม่ |

รายการที่ executable จริงและ assertions ของแต่ละรุ่นอยู่ใน [scenario catalog](../tests/auto-demo/catalog.mjs) ส่วนรายงานแต่ละรอบแสดงเฉพาะสิ่งที่รันแล้ว ความผิดพลาดที่คาดไว้ เช่น ผู้เรียนถูกปฏิเสธสิทธิ์ เป็นผลผ่านเมื่อสถานะที่สังเกตตรงตามข้อกำหนด

โจทย์ภาษาไทยใน catalog ใช้อธิบายความต้องการของ persona ตัวทดสอบทำผ่านคำสั่งที่ระบบรองรับ ไม่ใช่หลักฐานว่า AI เข้าใจ prompt อิสระทุกแบบหรือสร้าง domain ใหม่ได้ Invoice บน production ยังปิด upload และสาม domain ปัจจุบันยังจำกัดอยู่ที่ค่าขนส่ง, F=ma และเกมป้องกันด้วยโล่

## ประวัติจากห้องจริง

ผลรอบเปิดระบบเดิมอยู่ใน [รายงาน 18 ตุลาคม](../handoff/Final/planning-review/TABLETOP_R1_POST_DEPLOY_TEST_REPORT.md) และเก็บรายละเอียดการเปิดกติกาที่ผู้ใช้อนุมัติวันที่ 19 ตุลาคมไว้ใน [hosted activation history](auto-demo/hosted-activation-2026-10-19.json)

ห้องตัวอย่าง `Encounter Table` เปิดกติกา r1 แล้ว: ป้องกันเพื่อน, ใช้ 1 AP, ครั้งเดียวต่อเทิร์น ตรวจหลัง reload แล้วยังคง ACTIVE และมี revision 0/1 ให้เลือก ประวัติบันทึกทั้งการเปิดร่างเก่าที่ถูกปฏิเสธและการเสนอค่าเดิม → จำลอง → ตรวจ → อนุมัติ → เปิดใช้สำเร็จ โดยไม่มีคำขอ AI เพิ่ม

ข้อความปฏิเสธครั้งแรกไม่ระบุ server error code จึงยังไม่ยืนยันสาเหตุ แม้ระบบจะมีอายุ approval 15 นาที การทดสอบ expiry ในเครื่องเป็น regression แยก ไม่ใช่หลักฐานยืนยันสาเหตุของเหตุการณ์จริง

บันทึกนี้ตัดชื่อบัญชี, อีเมล, room ID, cookie, invitation และคีย์ออก ไม่ใช่ backup ทั้งระบบหรือ event log ฉบับเต็ม ไม่มีการ Reset ห้องจริง การทดสอบสองบัญชีบน host, มือถือ, recovery และเพดาน AI จริงยังแยกเป็นงานที่ต้องทำต่อ

## การรักษาประวัติ

- ห้องจริงยังเก็บสถานะและ revision ตามระบบเดิม แต่ Reset เป็นคำสั่งทำลายประวัติใน epoch เดิม จึงไม่ใช้ Reset เพื่อเตรียม auto demo
- ชุดทดสอบใช้ฐาน disposable ใหม่ ส่วน run artifacts อยู่นอกฐานนั้นและยังอยู่หลังจบการทดสอบ
- CI เก็บ run JSON/HTML เป็น artifact ตามระยะ retention ของ workflow; ไม่ใช่ archive ถาวร เลือกรอบที่ต้องส่งมอบและตรวจข้อมูลก่อนบันทึกเข้า `handoff/Final/auto-demo/` ใน Git
- ภาพหน้าจอของบัญชีจริงอยู่ใน ignored `test-results/auto-demo-hosted/` เฉพาะเครื่อง ไม่รวมในไฟล์เผยแพร่
