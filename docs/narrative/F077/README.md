## เรื่องเดียวที่ทั้งสามสื่อต้องส่งต่อ

**คุณมีงาน → เริ่มใช้ → เจอจุดที่ไม่พอดี → พิมพ์ขอปรับ → ตรวจ/ใช้ → เครื่องมือเปลี่ยนให้เข้ากับคุณ → ทำงานต่อบนโต๊ะเดิม**

เก้าอี้ ปากกา และค้อนเป็นคำเปรียบเทียบสั้น ๆ สำหรับเครื่องมือที่ช่วยให้คนลงมือทำสิ่งที่ตั้งใจ ไม่ใช่เรื่องประวัติผู้ก่อตั้งที่ยืนยันแล้ว และไม่ใช่การเปลี่ยน Tabletop ให้เป็นผลิตภัณฑ์เกี่ยวกับเฟอร์นิเจอร์

Belief: **The best tool is the one you don't have to think about.**

Product thesis: **Work defines what software becomes.**

ข้อเสนอหน้าบ้าน: **เครื่องมือที่ค่อย ๆ ปรับให้เข้ากับคุณ** / **Tools that keep adapting to you.**

## เกณฑ์รอบ 3: ทุกการเปลี่ยนต้องมีเหตุจากคน

| เหตุการณ์ | พิมพ์ขออะไร | เครื่องมือปรับอย่างไร | เห็นประโยชน์อย่างไร |
| --- | --- | --- | --- |
| เริ่มจดขาย | ช่วยทำโต๊ะจดขายกาแฟกับเค้ก | ตาราง2รายการ | เห็นยอด225 |
| ลูกค้าเยอะ กรอกไม่ทัน | เพิ่มปุ่มขาย กดครั้งเดียวเพิ่มจำนวน | ปุ่มกาแฟ+1/เค้ก+1 | กดกาแฟ จำนวน3→4 ยอด225→250 |
| อยากรู้ว่าอะไรขายดี | เพิ่มกราฟยอดขายแยกตามสินค้า | กราฟจากแถวเดิม | เปรียบเทียบยอด100กับ150 |
| ลองโปรช่วงบ่าย | เพิ่มส่วนลด10% | กฎและยอดสุทธิ | gross250 → net225 |
| อยากปรับโปร | เปลี่ยนกฎนี้เป็น20% | แก้เฉพาะกฎที่เลือกหลังตรวจ/ใช้ | net200; grossและข้อมูลเดิมยังอยู่ |

เว็บให้ลองส่ง/ตรวจ/ใช้คำขอและกดปุ่มที่เกิดขึ้น READMEเล่าจากปัญหาของคน คลิปแสดงการพิมพ์และผลในแต่ละจังหวะ ข้อความกับการ์ดที่เปลี่ยนต้องมองตามได้ก่อนเข้าสู่คำขอถัดไป

## บทบาทของแต่ละสื่อ

| สื่อ | ผู้ชมควรได้อะไร | จังหวะและรูปแบบ | สิ่งที่ไม่ยัดลงไป |
| --- | --- | --- | --- |
| หน้าเว็บ | รู้ในจอแรกว่าช่วยอะไร เห็นการเปลี่ยนแปลง แล้วเลือกลอง | Hero สั้น + บอร์ดที่กดเพิ่ม/แก้ได้, เรื่องเครื่องมือ, film 60s, งาน/เรียน/เล่น, CTA | ตาราง test/รุ่น library/บันทึก release |
| README | เข้าใจเหตุผล วิธีใช้ ขอบเขต และตามหลักฐานต่อได้ | Markdown อ่านเร็ว, poster ลิงก์วิดีโอ, รายการความสามารถ, วิธีเริ่ม 3 ขั้น, details ขอบเขต, ลิงก์เอกสารและ license | HTML layout ซับซ้อน, autoplay/audio, KPI ที่ไม่ได้วัด |
| วิดีโอ | จำภาพและหลักคิด เห็นว่าเครื่องมือเติบโตไปพร้อมงาน | 60s, เครื่องมือ 3 ชิ้น, บอร์ดเดียวที่เพิ่ม/แก้/แตกแขนง, ตัวเลขหนึ่งเรื่อง, end hold | วิธีใช้ทุกเมนู, รายชื่อ library, อ้างว่าเป็นการบันทึก AI ใช้งานจริง |

## ของเดิม → ร่างใหม่

| ด้าน | ของเดิมที่ตรวจ | ร่างใหม่ | เหตุผล |
| --- | --- | --- | --- |
| เปิดเรื่อง | Belief เป็น headline หลักทั้ง README/เว็บ | ประโยคบอกประโยชน์มาก่อน แล้วใช้ belief กับเก้าอี้ | ให้รู้ว่าผลิตภัณฑ์ทำอะไรตั้งแต่ต้น |
| ภาพ hero | SVG แนวคิด task table | ใช้บอร์ดตัวอย่างที่กดเพิ่ม/เปลี่ยนได้ และ film จากเรื่องเดียวกัน | ลดการมีหลายเรื่องที่คนต้องประกอบเอง |
| ที่มา | ช่าง/ครู/เพื่อนปรับเครื่องมือ; ไม่มีเก้าอี้ | เก้าอี้/ปากกา/ค้อน → เครื่องมือที่ปรับตามงาน โดยไม่มี morph | เพิ่มภาพจำโดยรักษาน้ำเสียง |
| เนื้อหาหลัก | Invoice / Physics / Encounter กระจายสามเรื่อง | ยอดขายหนึ่งเรื่องต่อเนื่องก่อน แล้วค่อยขยายสามบริบท | ทำให้เห็นกลไกที่เชื่อมความสามารถ |
| จุดเริ่มใน motion | วางไฟล์บทเรียนก่อน | พิมพ์โจทย์บนโต๊ะว่าง แล้วเพิ่มข้อมูลทีหลัง | ตรงกับ no-file-first ปัจจุบัน |
| ความสามารถ | ตาราง ปุ่ม กราฟ ฉาก | เพิ่มเก็บวิธีคำนวณไว้ใช้ซ้ำ, input→output, ถาม/แก้กฎเฉพาะใบ | ให้เห็นส่วนที่ลึกกว่าหน้าตา |
| สื่อเคลื่อนไหว | Remotion GIF 20s, 960×540, 12fps; ฟิสิกส์ 10→20N | Remotion MP4 draft 60s, 1280×720, 30fps; จดขาย → ขอปุ่มขาย → กด225→250 → ขอกราฟ → ขอส่วนลด10→20% | จังหวะคล่องและอ่านเลขได้; source แก้ต่อได้ |
| ความน่าเชื่อถือ | ภาพจำลอง + screenshots เดโมที่เตรียมไว้ | ยังคงป้าย provenance; แยกแผนบันทึกการใช้จริงไว้ใน evidence | ความสวยของ motion ไม่ใช่ผลพิสูจน์ runtime |

## รูปแบบหน้าเว็บที่ร่างใหม่

1. Header เบา: logo เดิม, ภาษา, CTA; เมนูร่าง/README/reference เป็นชั้นรอง
2. Hero สั้น: “เครื่องมือที่ค่อย ๆ ปรับให้เข้ากับคุณ” พร้อมบอร์ดขนาดใหญ่ที่กดเพิ่ม/แก้ได้ มือถือเรียงเนื้อหาให้อ่านก่อนลงมือ
3. บอร์ดใช้ข้อมูลตัวอย่างและแสดงป้ายชัดเจน: เพิ่มตาราง → ตรวจ/ใช้กฎ → ข้อมูลใหม่ → ตรวจ/ใช้ส่วนลดใหม่ ผลที่ใช้อยู่ไม่เปลี่ยนก่อน Apply
4. เครื่องมือสามชิ้นเป็นแถวเรื่องเล่าสั้น ตามด้วย film 60s; รูปแบบ section สลับน้ำหนัก ไม่ซ้อนกรอบข้อความแบบเดิมทั้งหน้า
5. เก็บ animation เดิม ภาพ Physics/Encounter และป้ายข้อมูล/ผู้เล่นจำลอง; CTA พาไป URL ที่มีอยู่จริง
6. Video มี controls, poster และ preload metadata; ไม่มี autoplay เสียง; reduced motion ใช้ still/manual control; เสียงและ subtitle tracks เป็นงาน final แยก

ร่างนี้ใช้ HTML/CSS/JS แยกใน docs เพื่อ review โครงและเรื่อง ยังไม่แก้ auth callbacks หรือ runtime เมื่อจะ integrate ค่อยย้ายเข้าผู้รับผิดชอบเดิม: `src/tabletop/ui/PublicWelcome.tsx`, `landing-copy.ts`, `public-welcome.css`, `docs/showcase/` และ README ที่ root

## การปรับทั้งสามรอบ

รอบแรกเป็นข้อความและวิดีโอ36s รอบสองเพิ่มบอร์ดและคลิป60s แต่ผู้ใช้ชี้ว่าของยังเกิดเองโดยไม่มีคำขอ รอบสามจึงใช้เหตุจากคนขายเป็นตัวเดินเรื่อง: กรอกไม่ทัน → พิมพ์ขอปุ่ม → กดขายได้; อยากรู้ยอดแยกสินค้า → พิมพ์ขอกราฟ; อยากลองโปร → ขอและแก้กฎที่เลือก รายละเอียดเปรียบเทียบอยู่ใน [references](references.md#เปลี่ยนจากร่างแรกตรงไหน)

## แผนผลิตและตรวจรับ

| ช่วง | ผลงาน | เกณฑ์ผ่าน |
| --- | --- | --- |
| 1 — ชุดร่างนี้ | แผน, copyTH/EN, README, storyboard, production prompt, silent animatic | เรื่องและตัวเลขตรงกัน; ทุกภาพจำลองมีป้าย; renderจริง/เปิดเล่นได้ |
| 2 — ภาพและเสียง final | 1920×1080/30fps, versionTH/EN, subtitles, poster; optional12s web cut | อ่านข้อความทัน, โทนแบรนด์, ไม่มี flash, เสียงไม่กลบคำ, ตรวจเฟรม cut และหลัง pause |
| 3 — บันทึก proof | คลิปใช้แอปจริง60–90sในห้องQAที่ได้รับอนุญาต | prompt→review/apply→ขอปุ่ม/กดขาย→ขอกราฟ→เพิ่ม/แก้กฎ→reload พร้อมreadback; ระบุช่วงตัด/เร่งเวลา |
| 4 — นำเข้าเว็บ/README | ใช้ copy/assetsที่ review แล้ว | mobile280/320/414, desktop, language parity, keyboard, links/auth unchanged, reduced motion/poster, media budget |
| 5 — judge companion | baselineก่อนงาน / ผลงานที่ทำระหว่างงาน / Codex evidence | มีcommit/PR/test/demoของงานใหม่; ไม่ตีความของเดิมว่าเป็นงานในวันแข่ง |

ไม่จำเป็นต้องรอ proof clip เพื่อ review copy/animatic แต่ห้ามเรียก animatic ว่า proof การสร้างสำเร็จจริง
