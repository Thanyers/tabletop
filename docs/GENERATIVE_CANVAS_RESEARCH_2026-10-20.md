# Research: Generative Canvas contracts, execution, and collaboration

ตรวจแหล่งข้อมูลปฐมภูมิเมื่อ 2026-10-20 · เอกสารนี้เป็นหลักฐานประกอบการวางแผน ไม่ใช่สัญญา implementation

## ข้อค้นพบหลัก

- **Observed — catalog ให้ความแปลกใหม่ด้านการจัดวาง ไม่ใช่สร้าง renderer ใหม่:** `json-render` จำกัด spec ไว้ที่ component ใน catalog และ map component เหล่านั้นไปยัง implementation ใน registry ของแอป; Apache-2.0. จึงสร้างชุดผสม/การจัดวาง/ข้อมูล/การกระทำใหม่จากชิ้นส่วนเดิมได้ แต่ primitive หรือ interaction ที่ไม่มี renderer อยู่แล้วต้องเขียนเพิ่ม [เอกสารและโค้ดตัวอย่าง json-render](https://github.com/vercel-labs/json-render/blob/main/README.md).
- **Observed — A2UI เป็น protocol ข้ามแพลตฟอร์ม ไม่ใช่ renderer สากล:** A2UI v0.9.1 ระบุเป็น production ปัจจุบัน, v1.0 ยังเป็น candidate; ตัวแทน client ต้อง parse/validate message, map component เป็น widget ของแพลตฟอร์ม, จัดการ lifecycle/data binding และ route action. Protocol ใช้ component ที่ client อนุมัติ; custom widget จึงยังต้องมี renderer ฝั่ง client [A2UI status/license](https://github.com/a2ui-project/a2ui/blob/main/docs/public/index.md) · [คู่มือ renderer](https://github.com/a2ui-project/a2ui/blob/main/docs/public/reference/renderers.md). Apache-2.0.
- **Inference — ควรเก็บ React Canvas ปัจจุบันไว้เป็น host:** ทำ contract แบบ versioned `ViewSpec`/`SceneSpec` แล้วเพิ่ม compositional primitives ที่ renderer มีจริง เช่น card, table, label, path, node/edge, axis, control และ timeline. ให้ AI เลือก/เชื่อม/จัดรูปแบบชิ้นส่วนเหล่านี้; component ใหม่ที่มี semantics ใหม่ยังต้องผ่าน implementation และ review ของเรา. วิธีนี้ยกระดับจาก demo คงที่โดยไม่อ้างว่า catalog ทำ arbitrary UI ได้.
- **Observed — tldraw ช่วยงาน whiteboard/direct manipulation แต่มีค่าใช้สิทธิ์และงาน shape:** custom shape ต้องมี `ShapeUtil` สำหรับ render, geometry, hit testing และ interaction; synced shape ต้องลงทะเบียน utility/schema ฝั่ง client และ server. Sync server เก็บเอกสาร canvas และทำ realtime sync ได้ แต่เอกสารผู้ให้บริการระบุว่ายังต้องเพิ่ม authz, rate/size limits, long-term snapshots และการค้นหารายการห้องเอง [custom shape contract](https://tldraw.dev/docs/shapes) · [sync architecture and gaps](https://tldraw.dev/docs/sync) · [custom shape sync](https://tldraw.dev/examples/sync-custom-shape).
- **Observed — tldraw SDK ไม่ใช่ dependency แบบ MIT สำหรับ production:** ต้องมี trial/commercial/hobby key; commercial key ใช้ production เชิงพาณิชย์ได้และราคาเสนอโดยฝ่ายขาย. ยังไม่พบราคาสาธารณะที่ยืนยันได้ [tldraw license keys](https://tldraw.dev/sdk-features/license-key) · [license/pricing](https://tldraw.dev/pricing). **Unknown:** ค่าใช้สิทธิ์ตามขนาด Tabletop และขอบเขต collaboration ที่ต้องการ.
- **Observed — Cloudflare Dynamic Workers เป็นทางออกสำหรับ server-side JavaScript ที่ผู้ใช้/AI สร้าง:** Worker Loader โหลดโค้ดขณะทำงานใน sandboxed Dynamic Worker; `globalOutbound: null` บล็อก `fetch()`/`connect()`, ไม่ส่ง `env` ให้โค้ดได้ และตั้งเพดาน CPU/subrequests ต่อ invocation ได้ [ตัวอย่าง AI code interpreter](https://developers.cloudflare.com/sandbox/get-started/build-an-ai-code-interpreter/) · [custom resource limits](https://developers.cloudflare.com/dynamic-workers/usage/limits/).
- **Observed — ตัวอย่าง Cloudflare จำกัด CPU และเวลารอแยกกัน:** ตัวอย่างใช้ `limits: { cpuMs: 50 }` และ `Promise.race` กับ timer ฝั่ง host. เอกสารบอกว่า timer ทำให้ host หยุดรอโค้ดที่รอแบบไม่ใช้ CPU แต่ไม่ได้ระบุชัดว่า promise ที่แพ้ race ถูกยกเลิกหรือ Dynamic Worker ถูกทำลาย. **Inference:** ถือ wall timeout เป็นขอบเขตการรอ ไม่ใช่หลักฐาน hard cancellation; ต้องทดสอบ cleanup/ค่าใช้จ่ายก่อนเปิดให้ผู้ใช้จริง [ตัวอย่างทางการ](https://developers.cloudflare.com/sandbox/get-started/build-an-ai-code-interpreter/).
- **Unknown — ยังไม่พบ option ใน Worker Loader ที่ตัด global clock หรือ random ออก:** Cloudflare ระบุว่า `Date.now()` ใน Worker คงที่ระหว่างช่วงที่โค้ดกำลังใช้ CPU เพื่อกัน side-channel; นี่ไม่ใช่ virtual clock ที่กำหนดซ้ำข้าม invocation และ `globalOutbound` ควบคุม network ไม่ใช่ time/random [Workers security model](https://developers.cloudflare.com/workers/reference/security-model/) · [Loader API](https://developers.cloudflare.com/dynamic-workers/api-reference/). อย่าเรียก JS ที่สร้างโดย AI ว่า deterministic เพียงเพราะถูก sandbox.
- **Inference — ใช้ Dynamic Worker เป็นเครื่องคำนวณที่ไม่มีสิทธิ์เขียน:** ส่ง input ที่มี snapshot, command, ruleset version, seed และเวลาที่กำหนดมาให้; คืน JSON ขนาด/ชนิดที่จำกัด แล้วตรวจ schema + bounds + domain invariants ก่อน server authority ตัดสินใจ. ส่วนที่ต้อง replay ได้ควรใช้ interpreter/DSL ที่ควบคุม clock/random หรือโค้ดที่ผ่านการตรวจ ไม่ฝากความถูกต้องไว้กับ JS อิสระ. Cloudflare เองเตือนว่าผลลัพธ์จาก sandbox ยังเป็น untrusted input ก่อนบันทึก/ใช้/แสดง [sandbox security](https://developers.cloudflare.com/sandbox/concepts/security/).
- **Observed — Cloudflare-first ทำได้ แต่ Dynamic Workers และ Containers ไม่อยู่บน Free:** Dynamic Workers ใช้ได้เฉพาะ Workers Paid; ราคาเอกสารระบุ 1,000 unique Dynamic Workers/เดือนรวม แล้ว $0.002 ต่อ Worker ต่อวัน, คำขอ 10M/เดือนและ CPU 30M ms/เดือนรวมกับ Workers usage ตามเงื่อนไขแผน. Workers Paid ขั้นต่ำ $5/เดือนต่อบัญชี; Containers ไม่มี usage ที่ Free และมี allowance ตามทรัพยากรในแผน $5 ก่อนคิดเพิ่ม [Dynamic Workers pricing](https://developers.cloudflare.com/dynamic-workers/pricing/) · [Workers/Containers pricing](https://developers.cloudflare.com/workers/platform/pricing/). ค่าเกิน allowance ขึ้นกับจำนวนเวอร์ชันโค้ดที่เรียก, requests, CPU, หน่วยความจำ/เวลาเปิด Container และ egress; ยังไม่ประมาณ usage จริง.
- **Observed — เลือก Dynamic Worker สำหรับ pure JS ที่เรียก capability ชัดเจน; Container สำหรับงานที่ต้องมี Linux:** Dynamic Worker รับเฉพาะ modules/methods/values ที่ host ส่งให้ แต่ไม่มี child process/native add-on และ Node compatibility บางส่วน; Container ใช้ Linux image ใน Firecracker microVM เหมาะกับ package/toolchain/process ที่คาดหวัง filesystem. ทั้งสองรูปแบบต้องมี host Worker เป็นผู้ authenticate และกำหนด capability; sandbox ไม่ทำหน้าที่แทน authorization [Cloudflare sandbox environments](https://developers.cloudflare.com/sandbox/concepts/) · [security boundaries](https://developers.cloudflare.com/sandbox/concepts/security/).
- **Observed — browser Web Worker ไม่ใช่ security boundary สำหรับโค้ดที่ไม่ไว้ใจ:** มันไม่เข้าถึง DOM โดยตรง แต่ใช้ `fetch()`/`XMLHttpRequest` ได้และผูกกับ origin ของแอป; API ที่ยอมรับ same-origin requests จึงยังเป็นความเสี่ยง [MDN Web Workers API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API) · [Worker constructor/security](https://developer.mozilla.org/en-US/docs/Web/API/Worker/Worker).
- **Observed — iframe sandbox แยกขอบเขตได้มากกว่า แต่ต้องแยก origin:** เปิดเฉพาะ token ที่จำเป็น เช่น `allow-scripts`; อย่าใช้ `allow-scripts` + `allow-same-origin` กับ iframe same-origin เพราะเนื้อหาอาจเอา sandbox ออกได้. เนื้อหาที่อาจเป็นอันตรายควรอยู่คนละ origin และยังต้องกันการเปิดหน้าโดยตรงนอก iframe [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe). Cloudflare เตือนเช่นกันว่า preview บน hostname ของแอปอาจใช้ app cookies/API และแนะนำ separate hostname [Cloudflare sandbox security](https://developers.cloudflare.com/sandbox/concepts/security/).
- **Inference — ถ้าต้องสร้าง JavaScript ที่วาด DOM/canvas เอง ให้ iframe คนละ origin เป็น phase หลัง:** ใช้ CSP จำกัด `connect-src`/ทรัพยากร, สื่อสารด้วย `postMessage` schema ที่ allowlist และไม่ส่ง secret/authority token. ยังต้องตรวจ output, origin, message rate/size และ keyboard/accessibility. โค้ดใน frame มีสิทธิ์ทำสิ่งใดภายใน frame ตาม capability ที่เปิดให้; การแยก frame ไม่ได้ทำให้ผลลัพธ์นั้นเชื่อถือได้.

## QuickJS/WASM สำหรับ custom behavior

- **Observed — QuickJS เป็น escape hatch สำหรับ logic ใหม่ โดยไม่ต้องให้ AI เขียน React หรือ renderer:** release ทางการ `2026-06-04` รองรับ ES2025 เกือบครบและ MIT; `quickjs-emscripten` ห่อ engine เป็น WASM สำหรับ browser และ Cloudflare Workers. Wrapper มี runtime/context แยกกัน, ปิด module loader ได้ และเปิด API ให้ engine เท่าที่ host กำหนด. [QuickJS release/license](https://bellard.org/quickjs/) · [quickjs-emscripten](https://github.com/justjake/quickjs-emscripten)
- **Observed — มี resource controls แต่ยังต้องวัดขอบเขตจริง:** `setInterruptHandler` ถูกเรียกเป็นระยะและใช้ทำ execution timeout ได้; มีเพดาน memory และ stack. เอกสารไม่ได้เรียก callback count ว่า instruction fuel แบบแม่นยำ และไม่ได้รับรองว่าทุก built-in ที่ใช้เวลานานถูกหยุดได้ทันที. wrapper ระบุว่าโครงการยังต่ำกว่า 1.0 และยังไม่ได้ security-audit. [QuickJS C API](https://bellard.org/quickjs/quickjs.html) · [QuickJSRuntime API](https://github.com/justjake/quickjs-emscripten/blob/main/doc/quickjs-emscripten-core/classes/QuickJSRuntime.md) · [wrapper status](https://github.com/justjake/quickjs-emscripten#status--roadmap)
- **Observed — Cloudflare รองรับ WASM แต่การโหลดต้องทำตอน build:** Workers `WebAssembly.instantiate()` รับ precompiled module; ตัวอย่าง quickjs-emscripten สำหรับ Cloudflare import `.wasm` เป็น `WebAssembly.Module` เพราะโหลด bytes/compile ขณะทำงานไม่ได้. README ระบุทดสอบกับ Wrangler 3.22.1 จึงยังไม่ยืนยัน compatibility/performance กับ runtime ปัจจุบัน; Cloudflare Workers ไม่มี threading/Web Worker API. [Cloudflare WASM](https://developers.cloudflare.com/workers/runtime-apis/webassembly/) · [wrapper Cloudflare instructions and support matrix](https://github.com/justjake/quickjs-emscripten#webassembly-loading)
- **Inference — ใช้ VM เดียวกันทั้ง browser/server กับสัญญา pure compute:** ส่ง `snapshot`, `command`, `logicalTime`, `seed` เข้า guest; ส่งกลับ typed JSON patch หรือ `SceneSpec` ให้ authority ตรวจ schema/bounds/invariants ก่อนรับรอง. ไม่ expose host I/O, DB, secrets, timers หรือ module imports; ซ่อน/แทน `Date` และ `Math.random` ด้วย logical clock/PRNG ที่กำหนดเอง. รัน WASM artifact และ wrapper รุ่นเดียวกันทั้งสองฝั่ง; บันทึก VM/version/seed/time ที่ใช้กับผล replay.
- **Inference — test ซ้ำอย่างเดียวไม่พิสูจน์ determinism ของ JavaScript อิสระ:** finite test corpus ยืนยันได้เฉพาะ inputs/paths ที่ทดสอบ. ECMAScript อนุญาตให้ฟังก์ชันคณิตศาสตร์บางตัวเป็น implementation-approximated; pin VM/WASM artifact, ระบุนโยบาย numeric/tolerance และเก็บกฎที่ต้อง replay อย่างเข้มงวดใน subset/DSL ที่แคบกว่า. [ECMAScript Math functions](https://tc39.es/ecma262/2024/multipage/numbers-and-dates.html#sec-math.sin)
- **Unknown — ความเข้ากันได้ของ wrapper กับ Cloudflare รุ่นปัจจุบัน, interrupt ที่ครอบคลุม worst-case built-ins, และคุณสมบัติ security ของการฝังในสภาพแวดล้อมจริง:** ต้องเป็น gates ใน spike; การมี memory/stack/interrupt API ไม่ได้พิสูจน์ resource isolation หรือ deterministic replay ด้วยตัวมันเอง.

## Multiplayer, state และ animation

- **Observed — Durable Object เข้ากับ authoritative room state:** DO หนึ่งตัวเป็น instance เดียว, single-threaded และมี persistent storage; Cloudflare อธิบายว่าเหมาะกับ coordination และ strong consistency รวมเกม turn-based. SQLite-backed DO storage มี transaction/atomicity สำหรับ storage operations [DO design rules](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/) · [SQLite storage transactions](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).
- **Observed — CRDT เป็น sync model อีกแบบ:** Yjs shared types sync/merge การแก้ไขร่วมกัน; awareness สำหรับ cursor/presence ไม่อยู่ใน persistent document และถูกลบเมื่อ peer offline [Yjs shared types](https://docs.yjs.dev/getting-started/working-with-shared-types) · [Yjs awareness/presence](https://docs.yjs.dev/getting-started/adding-awareness).
- **Inference — แยกสอง lane:** ให้ server รับรอง command, revision, turn/role, deterministic state transition และ append accepted domain event ใน transaction; clients render จาก projection/event stream. ใช้ presence และอาจใช้ CRDT สำหรับ viewport, cursor, selection, annotations หรือ layout ที่นโยบาย merge ยอมรับได้. ถ้าตำแหน่ง/เลย์เอาต์ต้องกลับมาใน session ใหม่ ให้ persist/snapshot อย่างชัดเจน; awareness อย่างเดียวไม่ใช่ persistence. อย่าให้ CRDT merge กลายเป็นผู้ตัดสินกติกา/ผลจำลอง.
- **Tradeoff — tldraw sync มี document authority ของตัวเอง:** TLSocketRoom เก็บสำเนาเอกสาร canvas แล้ว relay changes. ใช้ได้กับ layout canvas ถ้ารับ license/shape registration และเพิ่ม auth/history ที่ต้องการ; ไม่ควรนำเอกสารนั้นมาแทน Tabletop domain event authority [sync docs](https://tldraw.dev/docs/sync). การเก็บ layout และ canonical simulation events แยกกันช่วยให้ replay/ตรวจสอบผลได้โดยไม่ผูก semantics เกมกับการลาก shape.
- **Observed — Browser มี primitive พอสำหรับ 2D animation:** SVG วาง path/shape เป็น element ที่เลือก/อธิบายได้; Canvas วาด animation ได้แต่ภาพเป็น bitmap และ object ภายในไม่เป็น DOM ที่ assistive technology เข้าใจ. Canvas จึงควรมี semantic HTML/ตาราง/คำอธิบายและ keyboard controls ประกบ [MDN SVG animate](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/animate) · [MDN Canvas API/accessibility](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API).
- **Inference — เริ่มด้วย SVG สำหรับ cards/diagram ที่ต้องเลือก, focus และ inspect; ใช้ Canvas เฉพาะ layer ที่มีวัตถุเคลื่อนจำนวนมากและมี fallback:** Animation เป็นการแสดงผลของ accepted event หรือ playhead ที่กำหนด ไม่ใช่เขียนผลลัพธ์กลับ authority ทุก frame. เก็บ animation parameters/keyframes ที่แชร์ได้เป็น versioned data.
- **Observed — Motion เหมาะกับ microinteraction ของ HTML/SVG:** API รองรับ HTML/SVG, keyframes และ spring; เป็น library เสริม ไม่ใช่ contract สำหรับสร้าง renderer ใหม่ [Motion quick start](https://motion.dev/docs/quick-start) · [Motion animation API](https://motion.dev/docs/animate). **Inference:** ใช้เป็น renderer implementation ภายใต้ timeline/actions ที่ตรวจได้; อย่าให้ AI ส่ง arbitrary component code เข้าแอปหลัก.
- **Observed — Remotion มี Player ฝัง composition ใน React และปรับค่าตาม runtime ได้; server-side renderer เปลี่ยน composition เป็นไฟล์วิดีโอได้** [Remotion Player](https://www.remotion.dev/docs/player) · [rendering video](https://www.remotion.dev/docs/render). **Inference:** เป็นทางเลือก export/คลิปสอน/สรุปการจำลอง ไม่ใช่ live canvas ที่แก้ state ร่วมกันและส่ง domain commands.

## ข้อเสนอที่นำไปใส่แผนได้

1. **Spike 10–15 วันแรก ให้ทดสอบ catalog และ custom behavior ควบคู่กัน:** ทำ `ViewSpec`/`SceneSpec` ขั้นต่ำบน React host เดิม พร้อม catalog cards/diagram/actions; ใน lane เดียวกันให้ QuickJS/WASM รัน custom rule/animation logic หนึ่งกรณีที่มีประโยชน์จริงทั้งบน browser และ server ด้วย input/VM เดียวกัน. วัด novelty ที่ catalog ทำไม่ได้, latency/bundle, memory/stack/interrupt, no-I/O/time/random, output validation, replay/version pinning และความต่างผล browser/server; ถ้าต้องใช้ Cloudflare loader ให้ทดสอบ static WASM import และ plan/CPU limit ของจริง.
2. **ภาพและ direct manipulation:** เติม SVG primitives และ declarative timeline ที่อ้าง accepted events; ใช้ Canvas เฉพาะเมื่อวัดแล้วว่ามี object-density/performance need. บังคับ pause/reduced motion และเนื้อหาทดแทนสำหรับ canvas; iframe arbitrary visual code เป็นทางเลือกทีหลัง.
3. **Server execution ทางเลือก:** ถ้า QuickJS-WASM ไม่เหมาะกับ latency/compatibility หรือจำเป็นต้องโหลด modules แยกเป็นรายงาน ให้ทดลอง Dynamic Worker บน Workers Paid กับ no-env/no-network, explicit `seed`/`logicalTime`, low CPU/subrequest limits, host deadline และ JSON output caps. ผลลัพธ์เป็น suggestion ให้ authority ตรวจและ commit event. ก่อนเปิดวงกว้างให้พิสูจน์ cancellation, duplicate execution, egress denial, malicious output และ billable unique-worker cardinality; repeated-run results เป็นหลักฐานเฉพาะ corpus ไม่ใช่ proof.
4. **ย้าย canvas ไป tldraw ยังไม่ควรเป็นฐานก่อนทดลอง:** รอทราบค่า commercial license และพิสูจน์ว่า direct manipulation เป็นคอขวด; เพิ่ม Rive/Pixi/Remotion เมื่อมี use case ที่ native SVG/Canvas + React primitives ทำไม่ได้. Pixi/Rive ไม่ได้ประเมินราคา/ใบอนุญาตในรอบนี้.

## ประเด็นที่ยังไม่ยืนยัน

- **Unknown:** Worker Loader มี documented switch เพื่อตัด `Date`, `Math.random`, timers หรือ reflection API หรือไม่; เอกสารที่ตรวจไม่แสดง option เหล่านี้. หากใช้ QuickJS ต้องทดสอบการซ่อน built-ins และการตั้ง capability จริง; อย่าอ้าง deterministic replay จาก repeated-run tests เพียงอย่างเดียว.
- **Unknown:** timeout แบบ `Promise.race` terminate invocation ของ Dynamic Worker หรือหยุดเพียงการรอของ host; เอกสารตัวอย่างระบุเพียง “stops your Worker from waiting”.
- **Unknown:** ราคา commercial tldraw ที่เหมาะกับ Tabletop; หน้า pricing ให้คุยกับฝ่ายขาย.
- **Unknown:** throughput/latency/bill ของ dynamic components ที่มีผู้เล่นพร้อมกัน, และภาพบนมือถือ/การเข้าถึงจริง; เอกสารผู้ขายไม่ใช่ benchmark ของ workload นี้.
- **Not researched here:** model provider pricing, R2 object strategy, Workflows/background orchestration และเวลารวมของแผน; ให้รวมกับเอกสารแผนหลักเพื่อไม่ซ้ำกับการวิจัยอีกสาย.
