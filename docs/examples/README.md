# ไฟล์สำหรับลอง Shared data table

ข้อมูลจำลองสามแบบนี้มาจากชุด source ที่ใช้ทดสอบ generic table กับ AI จริง ไม่มีข้อมูลบัญชีหรือห้องจริง ใช้กับ [ขั้นตอนสร้างโต๊ะ](../USER_GUIDE_TH.md#สร้างโต๊ะจากไฟล์ของตัวเอง) ไม่ใช่ไฟล์รูปแบบเฉพาะสำหรับ `/demo`

เปิดไฟล์แล้วเลือก **Download raw file** ใน GitHub จากนั้นสร้าง Shared data table ใหม่และลากไฟล์นั้นลง Canvas ทำทีละโจทย์ หากใช้ staging ให้ประสานผู้ดูแลเรื่องห้องและงบทดสอบก่อน

| ไฟล์ | ข้อความขอร่างที่ใช้เริ่มได้ | ผลที่ต้องตรวจด้วยคน |
| --- | --- | --- |
| [equipment-loans.md](equipment-loans.md) | “สร้างโต๊ะยืมคืนอุปกรณ์ตามไฟล์ มีปุ่มยืมและคืน บันทึกผู้ยืมจากคนที่กด ยืมได้เมื่อว่าง คืนได้เฉพาะผู้ยืม” | ยืมกล้องแล้วไม่ว่าง; คนอื่นยืมซ้ำ/คืนแทนไม่ได้; คืนแล้วกลับมาว่าง |
| [team-shifts.json](team-shifts.json) | “สร้างตารางเวรตาม availability และที่นั่งในไฟล์ สลับเวรสองคนเป็นคำสั่งเดียว เริ่มจากเวรของตัวเอง ห้ามซ้ำ slot และห้ามย้ายไปเวลาที่ไม่ว่าง” | สลับ Ada/Bo สำเร็จโดยเปลี่ยนสองแถวพร้อมกัน; สลับกับ Cy ไปเวลาอื่นถูกปฏิเสธ |
| [river-race.txt](river-race.txt) | “สร้างเกมตามไฟล์ host เล่นเรือแดง member-1 เล่นเรือน้ำเงิน คะแนนเริ่มศูนย์ เพิ่มทีละสองเฉพาะเรือตัวเองในตาตัวเอง แล้วผ่านเทิร์น” | host เพิ่มแดง 0→2; อีกคนเพิ่มน้ำเงิน 0→2; ผิดเทิร์น/ผิดเรือถูกปฏิเสธ |

ชื่อปุ่มและรูปแบบร่างอาจต่างกันตามคำตอบ AI ตรวจ conditions/effects/role/seat และ source evidence ก่อน Simulate → Validate → Approve → Activate เสมอ ไฟล์กับ prompt ไม่ใช่หลักประกันว่าโมเดลจะให้ผลเหมือนรอบทดสอบทุกครั้ง

ลองเปลี่ยน River Race จาก +2 เป็น +3 ระหว่างเกมผ่านวงจร review แล้วตรวจว่าคะแนนเก่ายังอยู่ และ action ถัดไปเพิ่มสามจริง จากนั้นให้ทั้งสองบัญชี logout/login แล้ว resume โต๊ะเดิม

ชุด browser regression ที่ใช้ provider จำลองอยู่ที่ [`tests/generic-table-browser.mjs`](../../tests/generic-table-browser.mjs) ส่วนผลสองบัญชีจริงและข้อจำกัดของหลักฐานอยู่ที่ [acceptance](../GENERIC_TABLE_ACCEPTANCE.md) ตัวอย่างเหล่านี้ไม่สั่งเรียก provider หรือสร้างห้องเองจากการเปิดไฟล์
